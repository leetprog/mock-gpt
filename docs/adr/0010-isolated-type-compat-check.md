# Hand-written runtime types, isolated program for the ADR-0003 compat check

`@types/google-publisher-tag` declares `googletag` as a global ambient *value* (a namespace containing top-level `function` members — the classic pattern for typing a library loaded via `<script src>`), not an importable module; the file has no `import`/`export` statements at all. That means the moment anything in a TypeScript program references it, `googletag` becomes a real global binding in that entire program — confirmed empirically: forcing it in via a triple-slash reference against this repo's actual `src/` produced `Duplicate identifier 'googletag'` against `index.ts`'s own `declare global { var googletag: Googletag }`, plus a structural mismatch report. `tsc --listFiles` also confirmed the package is **not** auto-included today, which means the ADR-0003 compatibility promise currently has zero enforcement — nothing has ever actually checked our types against the official ones.

Given that, `src/types/googletag.ts` holds our own hand-written interfaces (`Slot`, `PubAdsService`, `Googletag`, event payloads, etc.), not a merge with or extension of the ambient namespace — the main build (`index.ts`'s global install) can never share a TypeScript program with the official package's ambient declaration. The actual ADR-0003 verification needs a separate, isolated program (its own `tsconfig`, not included in the default `npm run typecheck`) that references the ambient `googletag.*` types on one side and our hand-written types on the other, checking assignability in both directions without ever letting our runtime's `declare global var googletag` enter that same compilation. That isolated check is follow-up work, not part of the Slot/PubAdsService implementation it was discovered during.

## Considered Options

- Reference the ambient namespace directly from our own runtime types (e.g. `class Slot implements googletag.Slot`) — rejected: this is exactly the collision reproduced above; the ambient global and our own global installation target cannot coexist in one program.
- Skip the isolated check and rely on manual review for ADR-0003 compatibility — rejected: silently drops the one thing ADR-0003 was actually for (a checkable guarantee, not just "looks similar").
